# Local dictation implementation gates

The primary owner executes the tightly coupled app work. The notification diagnosis is an independent read-only worker. Existing owners retain Hush, Tool Shed, shared catalogs and Vault Git control.

1. Build `Murmur.Core` for text transformation, original preservation and a single session state machine. Run the executable regression harness in `tests/Murmur.Tests`.
2. Build `Murmur.App` for native recording, nonactivating overlay, shortcut registration, preferences/session UI, safe focus-bound insertion and bounded worker lifecycle. Keep all runtime/download/build output outside the synced Vault.
3. Qualify one frozen CPU engine/model candidate. Use `tools/benchmark.py` with a caller-owned synthetic/licensed corpus. Record hashes, WER limitations, latency, peak worker RAM and process exit. Rerun only affected cases or missing proof.
4. Use the task-owned native UI for saved settings/readback, narrow layout, cancellation and clean quit. Add test lifecycle bounds so verification never leaves a worker or hidden test window.
5. Prepare a safe owner-triggered insertion/voice exercise in an empty Codex draft. Verify clipboard preservation, focus drift, no duplicate text, no auto-submit and Hush mute/release. No background microphone test is permitted.
6. Freeze the candidate, obtain one integrated correctness/security review, fix actual findings, audit dependencies, install the exact private candidate and compare artifact/source identities. Startup remains opt in.
7. Create reviewed private Git history, compare local/remote heads, update `Projects/local-dictation/current-state.json`, generate/validate projections, and coordinate the shared documentation packet through Tool Shed. Report any actual enforcement blocker.

Remaining strategic boundaries are optional cloud authentication/spend and owner live microphone/real-call/creative acceptance. A build or synthetic replay is not completion of those gates.
